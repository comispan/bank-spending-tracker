Rules & memory

The two free tiers of the categorizer. A rule is a standing instruction you write and it always wins; memory is what the app learned from the categories you picked, plus a small seeded starter list. Changing anything here re-resolves every transaction that you did not set by hand — rows you categorized yourself are never overwritten.

Rules tier 1

A pattern is matched against both the merchant key and the line the statement printed, so either is a reasonable thing to write a rule about. Leave the category empty to write a rule that only changes the flow type — useful for marking something a transfer so it drops out of the spend total.

Merchant memory tier 2

seed is a guess shipped with the app; llm is a guess a model made about your merchants (tier 3) and nobody has checked; memory is a decision you made. Rows counts how many transactions each one currently answers — a seed matching nothing is a guess about a merchant you do not have, and costs nothing to leave. Correcting a guess of either kind turns it into a decision, permanently.
